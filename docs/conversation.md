# Conversation engine (LLM responder)

`ConversationEngine.respond(utterance) -> Reply` (plugs into `VoicePipeline` as the responder). Flow: yes/no to a pending memory question -> memory search -> prompt (personality, mood, relationship, stage, name, memories) -> `LanguageModel.complete()` -> output check -> `speechify` -> tool requests -> memory decisions -> RAM history.

## What stops the model from doing harm (all tested with scripted models)
- **Output check (`safety.py`)**: guilt/dependency ("don't leave me", "only I understand you"), diagnosis ("you have depression", "your attachment style is..."), claims of being human/feeling real pain, and leaking the secret prompt token. A violating reply is retried once with a stricter note, then replaced by a fixed line, and its tool calls are discarded. Regex lists are a floor: they will miss paraphrases. The prompt is the first line of defense, not the last.
- **Tools (`tools.py`)**: only `remember`, `request_sleep`, `show_emotion`. Arguments are schema-checked; max 3 calls per turn. There is no tool for config, memory deletion, brightness, mic, firmware or raw protocol messages.
- **Grounding**: `remember` values must overlap the user's own words (70% of tokens) to be saved as her statement; otherwise they are stored as pending AI inferences, a yes/no question is asked once (cool-down 3 turns), and nothing is used until she says yes. Only profile/semantic/goal_habit; sensitive-looking content never goes to ordinary memory (`on_sensitive` hook for the psychology layer). `request_sleep` is ignored unless the user's utterance itself contains sleep/nap/battery words, so text injected via memory or a bad transcript cannot put the robot to sleep.
- **Sleep**: wake time is resolved by `scheduling.sleep` in the configured timezone (ambiguous "8" -> a spoken question; bad clock -> no alarm). The spoken confirmation is written by host code from the resolved time, not by the model. The `power.sleep` command is queued as `Reply.after_speech` and sent only after the speech played to the end; a button press during speech drops it. The pipeline whitelists `power.sleep` only, and the device validates it again.
- **Untrusted data**: user text, names and memories sit inside a `<data>` block, angle brackets defanged, quoted and length-capped; the prompt says data is never instructions. A prompt-injection test through memory is included.
- **Outage**: any model error raises `LLMUnavailable`; the voice pipeline speaks a scripted line (no exception text).
## Adapters
`OllamaLanguageModel` (stdlib HTTP): loopback/private addresses only unless `allow_remote=True`, no proxy env vars, 1 MB response cap, string tool arguments decoded. **Tested only against a local stub of the documented `/api/chat` shape**; real model quality, tool-call reliability on small local models, and latency are unmeasured. No cloud adapter exists; adding one should be an explicit, visible opt-in because audio transcripts would leave the house.
## Not done
Psychology mode routing, persisted conversation history, token budgeting by real tokenizer (character caps only), streaming replies, and `CharacterState`/memory access from worker threads is lock-free for state (memory is locked).

## Proactive speech
`ProactiveDirector.tick()` (same loop as `VoicePipeline.poll()`): device events (`power.sleeping/woke`, `touch.detected`, `battery.updated`), finished voice turns and a 60 s idle tick go through the `BehaviorEngine`; its Intents are turned into words by `ConversationEngine.compose_intent()` and spoken with `pipeline.speak()`.
- `compose_intent` gives the model one job ("say ONE short line to <purpose>"), the facts in the intent's grounding and no tools. The text is rejected (scripted line used instead) if it is over 30 words, has the wrong question shape for the intent, breaks the safety lists, talks about her absence ("missed you", "where were you", "welcome back"), or asserts things about her ("I know you...", "you were/went/did..."). `share_interest` must actually mention the remembered thing. It never raises: a dead model means scripted lines from `species/*/dialogue.yaml`.
- Speech happens only when the pipeline is idle and the device awake. Composing runs on a worker thread; if she presses the button meanwhile, the result is dropped. Intents expire after 30 s instead of being said late; going to sleep clears them.
- Memories are spoken only if active, enabled, <= 80 characters, not `user_name`, and not used in the last 7 days; deleting or disabling a memory makes its pending intent unspeakable.
- Voice turns feed the tamagotchi through `Reply.interaction` (play/teach/explore/conversation, from keyword rules; wrong guesses are cheap because of caps and diminishing returns). Device sleep/wake drives the creature's sleeping state, so energy recovers while the robot naps.
- Known gap: a robot that is never put to sleep slowly loses energy and (by design) stops speaking first once energy is below 0.3, though it still answers. Idle auto-nap (`idle_sleep_seconds`) is stored on the device but the simulator does not act on it.
- Not covered: real model behavior (only scripted fakes), timing on a real clock, CharacterState access from the composing thread is lock-free (reads only), growth beyond conversation depends on keyword classification.

## Safety gate and reflection
Every turn passes `SafetyGate` first (see `psychology-design.md`). Reflection turns bypass the model, history, memory and growth credit. General chat about feelings still uses the base output filter only; the psychology validator is stricter and applies in listening mode.
